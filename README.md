# Motive · 海外汽车营销 Cowork

让客户的故事，成为团队有准备的下一步。

Motive 面向海外汽车经销商的销售、市场、客户运营与售后岗位。中文工作台，英语、阿拉伯语、德语客户内容；将客户画像、记忆、车源、任务和交付物放在同一工作空间。

## 1.2 版本：围绕客户工作的持续推进

这次只吸收两份参考方案里的用户流程与核心场景，保留 Motive 品牌、现有海外市场、Copilot SDK 接入方式及海报编辑器。

- **打开即有工作**：根据当前客户记录整理工作包，首页展示正在推进、需要同事完成的事和备好的海报；这些准备来自本地业务规则，不冒充模型推理或后台运行。
- **新线索到有效预约**：仅凭联系方式建档，补齐需要，准备策略、时段和海报；分别登记实际发送、客户明确接受和外部预约回执，最后建立接待任务。
- **反馈改变安排**：需求更正、改期、投诉与退订同步影响工作包、邀请海报、审核和待办。旧版本保留为历史；迟到的模型结果不能覆盖新事实。
- **同事的关键工作**：责任人、理由、所需结果与提醒时间放在一起；支持转派、延后、带回结果和暂停。
- **七类岗位**：销售、营销、客户经理、市场经理、区域负责人、售后、售前。新增线索交接、客户关系、活动复盘和跨店经营成果；复盘使用工作区实际登记量并列出成本、到店与收入缺口。
- **分群活动与晨报**：客户需求决定客群和体验；排除未结投诉、退订及不适合的生命周期。当地 08:00 内部晨报可改时间和时区；日程仍由可见页面检查。
- **保留可编辑视觉交付**：方形、竖版、Story，PNG / SVG 导出、阿拉伯语 RTL、海报修改后重新审核。业务草稿与模型成果在界面中区分来源。

真实 Copilot 依赖安装、模型调用和 Azure 部署仍待完成。规则工作包和海报编辑可独立使用；AI 请求失败会保留失败，不自动冒充调用成功。

## 本地运行

要求 Node.js 22+。默认使用真实 Copilot；先安装服务端依赖与 Copilot CLI，并为服务运行账户完成登录：

```sh
npm install
npm install -g @github/copilot
copilot
```

按 CLI 提示登录，然后验证真实生成并启动：

```sh
npm run check:copilot -- --generate
npm start
```

默认地址为 `http://127.0.0.1:4173`。模型凭据仅由服务器读取。若使用环境文件，复制 `.env.example` 为 `.env`，通过 `node --env-file=.env server.js` 启动；`npm start` 不会自动加载 `.env`。

仅体验模板与界面可明确选择演示模式（PowerShell）：

```powershell
$env:AI_PROVIDER = 'demo'
node server.js
```

演示模式显示“模板演示”，不调用大模型。海报编辑与导出不依赖大模型。

## 体验路径

1. 在首页打开 Sarah 的“充电体验”工作：查看为什么这样安排、同事需要带回什么，以及为她准备的邀请海报。
2. 选择当地候选时间，或登记已由门店核实的未来时段；确认策略、编辑并审核海报，再确认当前活动。
3. 在外部渠道真实发送后记录发送事实。在“客户有了新变化”中录入“我考虑一下”，不能登记预约；只有明确接受所选时段并提供真实预约回执后才显示已登记预约。
4. 录入改期，旧回执转入历史、候选安排和海报更新。录入未结投诉，工作转给售后，促销暂停；解决必须记录客户确认依据。
5. 到“需要你”转派或延后同事工作，到“客户与画像”快速录入仅有联系方式的新咨询，或更正 / 停用已有记忆。
6. “营销活动 → 分群名单”查看不同需要、语言、时区及排除原因，为具体客群生成内容与海报；“持续任务”查看晨报和分群日程。
7. 已配置真实模型后可在同一工作中完善话术和海报，修改事实会带入新请求。失败和取消均保留实际状态。

## 当前范围

初始客户、车源、价格、意向评分和接待时段为虚构示例。手动登记门店时段与预约回执仍是人工记录，并不等于已连接外部日历。客户记忆、任务与交付物仍保存在当前浏览器的 localStorage，不同设备不共享。服务器提供登录、模型调用与静态资源，没有团队数据库或分用户权限。

自动化只在页面打开且可见时检查，关闭后停止。WhatsApp、邮件、CRM/DMS 与后台持续调度未连接；生成和审核不会发送消息。海报中的 SUV 是示意插画，发布前需核实真实车型与活动事实。
