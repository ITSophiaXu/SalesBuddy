# Motive · 海外汽车营销 Cowork

## 1.6：对话积累画像，恢复汽车营销的业务入口

CRM 导入只是基础资料。销售在 AI 协作（Cowork）中描述客户沟通，系统整理需求、预算、顾虑、购车时间和决策条件。销售核对后写入客户画像，并保留原话、来源、时间和会话。补充、替换与更正均保留历史；推测不会覆盖已确认事实。后续话术、选车、转化计划和活动分群参考最新画像。

- 导航直接进入 **AI 协作、工作台、客户与画像、车源与方案、营销活动、资料与连接**。
- 车源与方案保留客户匹配、车型方案和费用试算；营销活动保留分群、活动包与海报。
- 画像提议不会创建任务，也不会自动记录联系、预约或成交；确认后旧版材料提示资料已更新。
- Copilot 对话协议增加画像提议，并校验每条信息的销售原话；真实连接检查增加第五项“销售对话整理画像”。原始源码包未安装 SDK；运行环境的实际连接以服务状态为准。

本发布分支同时保留线上兼容修复：安全 Markdown、实时执行状态与公开回复、停止与重试，以及显式免登录配置。SDK `1.0.13`、CLI `1.0.83`、Marked `18.0.11` 固定在依赖锁中；SDK 会话使用 `disconnect()` 清理。真实 AI 请求失败不会降级为演示回复。CRM 等实时系统未连接，客户与工作数据仍保存在当前浏览器。

最新操作步骤见 [开始使用](开始使用.md)。以下版本说明为历史记录，以本节为准。

## 1.5 版本：在同一项任务里推进工作（历史说明）

“AI 协作”不再是独立入口。Cowork 用来对话和完成工作；工作台是同一份任务、待办和成果的管理视图。

- 任务可设置目标、负责人和日期；在“下一步与反馈”安排具体动作、负责人、完成时间和所需结果。待办可在工作台集中回报，结果回到原对话。尚有未完成待办时不能标记整项工作完成。
- 从任务显式记录客户回复、需求变化、顾虑、未回复或服务问题。保存后带上最新事实继续调整方案；普通聊天和待办回报不会自动变成客户事实。未回复不改变意向分数或销售阶段。
- 新增销售线索只需电话和已有信息，预算与意向保留待确认；保存后进入该客户的 Cowork 转化任务。
- 任务链接保存对话身份，刷新和浏览器前进后退仍能接续。输入草稿保留；全局搜索可查电话、任务目标和成果。旧成果准备记录第一次打开时归入 Cowork，重复打开不会新增任务。
- 活动记录的方案入口使用门店市场，并接续同一项活动任务。资料侧栏可选择是否引用品牌知识和车型资料，选择实际作用于对话及成果请求。
- 完整测试通过 112 项，覆盖业务规则、界面操作控制器和 HTTP 服务；界面控制器测试不是浏览器视觉验收。

## 1.3 版本：从对话开始，需要时交付成果（历史说明）

- **显眼的对话入口**：首页工作列表上方的大输入框、侧栏“和 Cowork 对话”、全局“问 Cowork”和客户工作页入口。
- **正常连续对话**：普通问题直接回答，保留本地历史；支持继续追问、新对话、停止和重试。无需为一般问题选择客户。
- **按意图准备成果**：真实模式由 Copilot 结合最新消息、历史与客户上下文选择回答、澄清或生成；讨论“海报怎么设计”不会仅因出现关键词就创建海报。生成的文案和海报直接显示在对话里，也归入交付物。
- **在原稿上继续**：支持“短一点”“换成阿拉伯语”等成果修订。只要文字时不强制生成海报；客户事实或原稿变化后，不采用迟到的旧结果。
- **清楚关联客户**：可选择客户或识别唯一姓名；另一位客户进入独立对话。客户成果缺少对象时先澄清，选择后继续原请求。聊天本身不自动改写客户事实、发信或登记预约。

普通问答与语义判断需要真实 Copilot 连接。`AI_PROVIDER=demo` 仅提供明确标注的有限本地对话示例，不能代替开放式模型问答。真实连接仍待完成。

## 1.2 版本：围绕客户工作的持续推进

这次只吸收两份参考方案里的用户流程与核心场景，保留 Motive 品牌、现有海外市场、Copilot SDK 接入方式及海报编辑器。

- **打开即有工作**：根据当前客户记录整理工作包，首页展示正在推进、需要同事完成的事和备好的海报；这些准备来自本地业务规则，不冒充模型推理或后台运行。
- **新线索到有效预约**：仅凭联系方式建档，补齐需要，准备策略、时段和海报；分别登记实际发送、客户明确接受和外部预约回执，最后建立接待任务。
- **反馈改变安排**：需求更正、改期、投诉与退订同步影响工作包、邀请海报、审核和待办。旧版本保留为历史；迟到的模型结果不能覆盖新事实。
- **同事的关键工作**：责任人、理由、所需结果与提醒时间放在一起；支持转派、延后、带回结果和暂停。

- **分群活动与晨报**：客户需求决定客群和体验；排除未结投诉、退订及不适合的生命周期。当地 08:00 内部晨报可改时间和时区；日程仍由可见页面检查。
- **保留可编辑视觉交付**：方形、竖版、Story，PNG / SVG 导出、阿拉伯语 RTL、海报修改后重新审核。业务草稿与模型成果在界面中区分来源。

## 本地运行

要求 Node.js 22+。默认使用真实 Copilot；先安装服务端依赖与 Copilot CLI，并为服务运行账户完成登录：

```sh
npm install
npm install -g @github/copilot
copilot
```

按 CLI 提示登录，然后验证真实生成并启动：

```sh
npm run check:copilot -- --generate
npm start
```

默认地址为 `http://127.0.0.1:4173`。模型凭据仅由服务器读取。若使用环境文件，复制 `.env.example` 为 `.env`，通过 `node --env-file=.env server.js` 启动；`npm start` 不会自动加载 `.env`。

仅体验模板与界面可明确选择演示模式（PowerShell）：

```powershell
$env:AI_PROVIDER = 'demo'
node server.js
```

演示模式显示“模板演示”，不调用大模型。海报编辑与导出不依赖大模型。

## 体验路径

对话体验：在首页问“Sarah 现在最需要解决什么问题？” → 继续问“为什么？” → 说“帮她写一段简短英文跟进话术” → 从聊天打开成果 → 继续说“换成阿拉伯语”。普通讨论只留在聊天里，明确需要可用内容时再创建成果。真实问答需先连接 Copilot；可明确使用演示模式检查基础流程。

1. 在首页打开 Sarah 的“充电体验”工作：查看为什么这样安排、同事需要带回什么，以及为她准备的邀请海报。
2. 选择当地候选时间，或登记已由门店核实的未来时段；确认策略、编辑并审核海报，再确认当前活动。
3. 在外部渠道真实发送后记录发送事实。在“客户有了新变化”中录入“我考虑一下”，不能登记预约；只有明确接受所选时段并提供真实预约回执后才显示已登记预约。
4. 录入改期，旧回执转入历史、候选安排和海报更新。录入未结投诉，工作转给售后，促销暂停；解决必须记录客户确认依据。
5. 到“需要你”转派或延后同事工作，到“客户与画像”快速录入仅有联系方式的新咨询，或更正 / 停用已有记忆。
6. “营销活动 → 分群名单”查看不同需要、语言、时区及排除原因，为具体客群生成内容与海报；“持续任务”查看晨报和分群日程。
7. 已配置真实模型后可在同一工作中完善话术和海报，修改事实会带入新请求。失败和取消均保留实际状态。

## 当前范围
