# motive cowork

**今天，一起推进什么？**

motive cowork 是面向汽车经销商销售、市场与客户运营团队的 AI 协作工作空间。用对话讨论问题、整理客户反馈、准备话术；需要持续推进的工作，则进入可编辑、可追踪的任务工作台。

它不是只有聊天回复的界面：方案、海报和车型对比可以形成独立成果，继续修改、审核和导出。AI 能力由 **GitHub Copilot SDK** 提供，真实模式失败时不会退回固定模板冒充成功。

**当前版本：1.8.2** · [在线访问](https://brand-containing-test-estimation.trycloudflare.com) · [部署说明](DEPLOYMENT.md)

> 在线地址是临时公网入口，可能随隧道变化。当前实例使用真实 Copilot 模型，但初始客户、车型、价格和历史示例成果仍是演示资料，不代表已接入真实 CRM。请勿在公开免登录实例中录入敏感客户资料。

## 一个对话入口，六个清晰的工作区域

| 入口 | 可以做什么 |
|---|---|
| **AI 协作** | 从首页大输入框开始，讨论问题、写短话术、记录客户沟通或交代任务；从最近对话继续已有工作。 |
| **工作台** | 管理任务、待办和成果；按销售、市场、区域经理视角使用专业工作流，查看工作概览与 AI 来信。 |
| **客户与画像** | 新增线索、导入客户 CSV、查看已有资料；将销售原话整理为画像提议，核对后再保存。 |
| **车源与方案** | 查看同市场车型、结合客户需求匹配车源、试算费用，为车型对比准备资料。 |
| **营销活动** | 创建活动、查看分群名单、准备活动包与海报；分群考虑客户需要、联系许可和服务状态。 |
| **资料与连接** | 管理工作区资料与品牌知识，配置内置能力、Skills 和 MCP 接入需求。 |

普通问答和短话术留在完整对话中，不会因为提到“方案”或“海报”就自动创建成果。明确需要交付物时，工作台以**中间成果、右侧对话**呈现，任务信息和后续动作保持在同一项工作里。

## 从对话到可交付成果

### 问问题、写话术、积累画像

可以直接在首页输入：

> 为什么客户试驾后不回复？帮我梳理两种可能，并写一句自然的跟进话术。

关联具体客户后，可以记录实际沟通：

> 沟通记录：客户需要放两个儿童座椅，太太希望一起试驾后决定，计划月底购车。

画像提议需要销售核对确认，保留原话与来源；不会把推测直接写成已确认事实。之后的方案可以参考更新后的客户需求，已有材料也会提示资料变化。

### 制作车型对比：如何指定 2–3 款车

**当前通过文字指定车型，没有车型多选框。** 车型需要来自同一个市场，并与所选客户的市场一致；不清楚名称时，可先在“车源与方案”查看已有资料。

1. 打开 **工作台**，选择销售视角，进入 **制作车型对比**。
2. 选择客户，在 **车型与比较重点** 文本框填写 2–3 款车型名称和关注点。也可以稍后在右侧对话中补充。
3. 点击 **进入工作台**，确认右侧的工作要求，再点击 **发送**。
4. 生成后，在中间查看图文对比；通过 **审核与导出 → 导出客户对比页** 导出独立 HTML。

也可以直接从首页发起，例如使用内置美国市场示例客户：

> 为 Sarah 比较 Tesla Model Y 和 Toyota RAV4 Hybrid，侧重家庭空间、购车预算和补能便利，生成中文车型对比方案。

继续调整当前成果：

> 请调整当前车型对比，把用车成本放在最前面，其他重点和两款车型保留。

对比页使用工作区中的车型与价格记录，展示车型示意、资料来源和待核实项。示意图不是实车照片，示例价格不是正式报价；缺少的配置和费用应由门店核实。

### 方案、海报与版本管理

- 生成线索转化方案、跟进计划、营销活动包及多语言海报，支持中文、英语、阿拉伯语和德语成果。
- 手动编辑和 AI 修改都保留历史版本；右侧对话参考中间**当前选中的具体成果与版本**。
- 未保存的编辑会阻止 AI 基于旧稿继续修改；修改文档和修改海报不会无故重做另一份成果。
- 文档可导出 Markdown，海报可导出 PNG / SVG，车型对比可导出客户 HTML。未审核成果保留草稿标记。

## 本地启动：连接真实 Copilot

需要 **Node.js 22+、npm、可用的 Copilot 服务账户及相应模型权限**。运行环境还需能访问 npm 和 GitHub Copilot 服务。

### 1. 获取代码并安装锁定依赖

以下为 Windows PowerShell 示例：

```powershell
git clone --branch release/v1.8.2 https://github.com/ITSophiaXu/SalesBuddy.git
Set-Location SalesBuddy
npm ci
Copy-Item .env.example .env
```

已有工作目录或 `.env` 时，保留原配置，不要直接覆盖。本仓库已包含依赖锁，不需要另行全局安装 Copilot CLI。

### 2. 配置并登录

编辑 `.env`，保留真实模式，并设置账户可用的模型：

```dotenv
AI_PROVIDER=copilot
COPILOT_MODEL=gpt-6-astra
MOTIVE_AUTH_MODE=password
PUBLIC_ORIGIN=http://127.0.0.1:4173
```

同时设置自己的 **`MOTIVE_PASSWORD`（至少 16 个字符）**，或通过 `MOTIVE_PASSWORD_FILE` 指向私有密码文件。不要把实际密码、令牌或身份文件提交到仓库。

```powershell
npm run login:copilot
```

按 CLI 提示完成登录。登录需要属于运行服务的账户；浏览器或其他开发工具中已登录 GitHub，不代表该服务账户已登录。若账户没有 `gpt-6-astra` 权限，改用其可用模型，或将 `COPILOT_MODEL` 留空使用服务默认模型。

### 3. 确认真正可用并启动

```powershell
npm run check:copilot
npm run verify:copilot
npm start
```

打开 <http://127.0.0.1:4173/#home>。

`check:copilot` 查看依赖和连接准备状态；`verify:copilot` 使用内置虚构资料进行真实对话、画像提取及方案/海报调用，**可能产生账户用量**。仅有登录状态或健康接口成功，不等于已经完成模型调用。

服务及连接检查会自动读取项目根目录的 `.env`，进程环境变量优先。真实请求失败会明确显示错误，不会静默切换到 `demo`；`AI_PROVIDER=demo` 只用于明确选择的本地模板预览。

### 常用配置

| 配置 | 用途 |
|---|---|
| `HOST` / `PORT` | 默认本机 `127.0.0.1:4173`。 |
| `COPILOT_MODEL` | 指定可用模型；留空使用 Copilot 默认模型。 |
| `COPILOT_CLI_PATH` | 可选覆盖；默认自动发现项目内安装的 CLI。 |
| `COPILOT_GITHUB_TOKEN_FILE` | 可选私有身份文件；优先使用服务账户已有的 CLI 登录。 |
| `COPILOT_TIMEOUT_MS` | 模型请求超时，默认 `120000` 毫秒。 |
| `MOTIVE_MAX_CONCURRENT` | 模型并发上限，默认 `2`。 |
| `MOTIVE_AUTH_MODE` | 默认 `password`；`none` 显式开启匿名访问，需要自行评估暴露范围和账户用量风险。 |
| `MOTIVE_PASSWORD` / `MOTIVE_PASSWORD_FILE` | 工作区访问密码；后者指向私有文件。 |
| `PUBLIC_ORIGIN` | 请求来源校验配置，须与实际访问及反向代理配置一致。 |

## 当前能力边界

| 能力 | 当前实现 |
|---|---|
| 模型执行 | Copilot SDK 真实问答、结构化生成和信息提取；支持流式公开回复、执行状态、停止与重试，不展示模型内部推理原文。 |
| 客户与工作数据 | 保存在当前浏览器、当前站点来源（origin）的 `localStorage`，没有跨设备共享的团队数据库。清除站点数据会影响本地工作记录，更换域名也不会自动迁移这些数据。 |
| 模型上下文 | 选用的客户、车型和知识内容会发送到服务端及模型；“本地存储”不表示模型推理完全在本地进行。 |
| 角色与权限 | 销售、市场、区域经理是工作视角，不是企业级人员权限隔离；工作区密码也不是多用户账号体系。 |
| CRM / DMS 与外部数据 | CSV 是导入快照；实时 CRM、库存、订单、收款和外部日历接口尚未接入。 |
| 插件、Skills 与 MCP | 内置工作能力和工作要求模板可用；保存 MCP 服务地址仅记录配置，不代表已建立连接或能调用远程工具。 |
| AI 来信与日程 | 包含明确标识的本地规则简报及任务成果；日程只在页面打开且可见时检查，不是全天候服务器调度。 |
| 对外执行 | 不会自动发送 WhatsApp / 邮件、写回 CRM 或完成预约；当前模型会话没有开放终端执行和外部写入工具。 |

生成、审核与导出都不等于对外发送或业务成交。正式使用前，应核实客户授权、车型配置、价格、活动权益和实际业务回执，并导出重要成果备份。

## 开发与项目结构

前端为原生浏览器 ES Modules、HTML 和 CSS，无需前端打包步骤；Node.js 服务提供静态资源、访问控制及模型接口。

依赖固定为 `@github/copilot-sdk` **1.0.13**、`@github/copilot` **1.0.83**、`marked` **18.0.11**，以 [package.json](package.json) 和 [package-lock.json](package-lock.json) 为准。更新依赖时应同步更新声明、锁文件与部署参数。

| 文件 | 职责 |
|---|---|
| [app.js](app.js) | 应用状态、导航与业务页面编排。 |
| [chat-ui.js](chat-ui.js) / [ai-client.js](ai-client.js) | 对话、上下文、流式请求与执行状态展示。 |
| [workbench-ui.js](workbench-ui.js) / [artifact-workbench.js](artifact-workbench.js) | 成果编辑、当前选择、版本及导出。 |
| [vehicle-comparison.js](vehicle-comparison.js) / [poster.js](poster.js) | 图文车型对比和海报呈现。 |
| [experience-model.js](experience-model.js) / [experience-ui.js](experience-ui.js) | 岗位工作流、工作概览、AI 来信和生态配置。 |
| [server/copilot.js](server/copilot.js) | SDK 会话、模型调用、超时、取消与资源清理。 |
| [server/chat.js](server/chat.js) / [server/protocol.js](server/protocol.js) | 对话意图及结构化请求/结果校验。 |
| [tests](tests) | 业务规则、UI 控制器、HTTP、SDK 适配及发布文件覆盖。 |

```powershell
npm test
.\scripts\package-release.ps1
```

打包脚本生成源码 ZIP、SHA-256 摘要及逐文件哈希清单 [RELEASE.json](RELEASE.json)，排除依赖目录、运行凭据和本地业务数据。源码测试与打包记录不替代目标环境中的真实模型调用。

服务接口：`GET /healthz` 返回版本与基础健康信息；`GET /api/status` 返回模型、访问模式和连接状态；`POST /api/chat`、`POST /api/generate` 支持 JSON 或协商使用 `application/x-ndjson`。`verified` 表示当前服务进程已经有成功的真实模型调用，重启后会重新累计。

## Azure 部署与回退

完整流程见 [DEPLOYMENT.md](DEPLOYMENT.md)：在独立目录准备候选版本，配置服务账户，完成真实调用后再切换服务，并保留上一版镜像、源代码和运行配置。

Copilot 身份和缓存放在持久卷中；不要把凭据写入镜像，也不要在升级或回退时删除这些卷。长期公网使用应配置稳定的 HTTPS 域名与适当的访问控制，而不是依赖临时隧道。

**Git 提交与 Azure 发布是独立操作。** 本仓库不提供自动部署版本分支的工作流；修改代码或推送分支后，仍需单独发布到服务器。已打开的浏览器页面需要刷新，才能加载新的应用代码。
